# Contributing to Genesis

Thank you for your interest in contributing to Project Genesis!

Genesis is built under strict architectural invariants that protect consumer privacy and engineering integrity. Before submitting pull requests, please read our core contribution rules.

---

## 1. The Non-Negotiable Rule: Claims Are Measured, Not Asserted

We do not accept subjective performance assertions or unverified benchmarks.
1. **Never commit a performance claim without a benchmark artifact:** If you state that Genesis achieves $N$ lines per second or that query latency is $X$ microseconds, your PR must include a reproducible markdown report generated by `make bench-report`.
2. **Every benchmark report must record full environment telemetry:** The output must record the CPU model, core count, RAM, operating system, Go version, and git commit hash.
3. **Never weaken a test to make it pass:** If a test is modified, your commit message must explain mathematically or architecturally why the prior test assertion was incorrect. Missed targets must be reported honestly.

---

## 2. Standard Library Only for the Core Engine

Genesis has **zero external third-party dependencies**.
* The core server, parser, skip-lists, CLI, and embedded UI must remain 100% buildable with the Go standard library alone.
* If a feature would require an external dependency (such as YAML or TOML parsers, third-party logging frameworks, or external key-value stores), use standard library alternatives (JSON, flags, stdlib `net/http`) or reject the feature.
* Any proposed dependency requires an Architecture Decision Record in `docs/DECISIONS.md` before discussion.

---

## 3. Privacy & Egress Invariants

* **Volatile Memory by Default:** Logs must live strictly in RAM unless persistence is explicitly enabled via `--data-dir`.
* **Zero External Network Egress:** The embedded web UI must never load external fonts, analytics, tracking scripts, or CDN bundles. Every UI asset must be verified with test coverage asserting zero occurrences of `http://` or `https://`.
* **Amnesiac Purge (Burn):** The `genesis burn` command and `DELETE /logs` endpoint must completely purge all partition data, dereference structures for immediate garbage collection, and leave zero disk footprint.

---

## 4. Development & Testing Workflow

Before committing:
```bash
# 1. Run all unit and integration tests
make test

# 2. Run race detector
make race

# 3. Run linter
make lint

# 4. Generate official benchmark report
make bench-report
```
Use conventional commit prefixes: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
